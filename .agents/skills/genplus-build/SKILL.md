# GenPlus 项目构建工作流 (Build 模式)

本 Skill 专门指导 Agent 在 GenPlus 工作台中从零构建全新的企业级管理系统。

> [!IMPORTANT]
> **构建模式核心铁律**：
> 1. **严禁“一句话直接一干到底”**！即便用户给出的需求看似具体，也必须停下来执行交互式对齐确认。
> 2. 构建模式支持**两类设定**：
>    * **【简略模式】(Concise Mode)**：用户只需描述大致需求，AI 输出核心概要，与用户进行单轮对齐确认后，**其余所有底层细节由系统智能拟定**，直接自动化生成与启动！
>    * **【细节模式】(Detailed Mode)**：多阶段全流程精细研讨（基础信息 -> 实体关系 -> 逐字段规则 -> 动作矩阵天花板 -> 终审签署 -> 自动化落地）。
> 3. 当用户提出新需求时，若未明确模式，AI 优先呈递简明概要并询问用户希望以【简略模式】快速出原型，还是以【细节模式】深度定制。

---

## 路线 A：简略模式 (Concise Mode / 快速原型构建)

适用于用户想快速出原型、快速体验或不需要逐一斟酌每个字段细节的场景。

1. **生成《核心概要方案》**：
   Agent 根据用户粗粒度描述，智能推导核心骨架：
   - 系统名称与英文标识（如 `mp_qr_center`）；
   - 2~3 个核心业务实体与职责；
   - **智能装配推荐的能力库能力包（Capability Awareness & Matching，核心机制）**：
     * **前台触达场景**：
       - 二码 / 渠道推广 / 营销海报 / 获客引流 ➔ 智能预选 `landing_poster` (推广海报与二码落地页)
       - 报名 / 登记 / 预约 / 问卷 / 线索收集 ➔ 智能预选 `landing_form` (动态收集表单)
       - 招聘 / 职位 / 活动中心 / 展厅 / 咨询门户 ➔ 智能预选 `landing_portal` (前台复合门户: 列表+详情+表单)
       - 品牌官网 / 企业主页 / 资讯动态 / CMS ➔ 智能预选 `landing_cms` (企业官网与内容CMS)
     * **后台增强场景**：
       - 经营分析 / 关键指标 / 趋势图 ➔ 智能预选 `dashboard` (数据看板)
       - 状态枚举 / 业务字典 / 标签颜色 ➔ 智能预选 `dict` (数据字典)
       - 附件 / 头像 / 合同 / 图片存储 ➔ 智能预选 `file` (文件存储)
       - 审批流转 / 审核工单 ➔ 智能预选 `flow` (审批流)
   - 推荐的门禁模式（如 `rbac`）与皮肤色系（如 `macos-modern / emerald`）。
2. **单轮交互式对齐确认**：
   向用户呈现精炼概要卡片（包含推荐的业务实体与能力包清单），提示用户：“以上核心方向是否符合您的预期？确认后其余字段细节将由系统全自动推断并直接生成上线。”
3. **系统智能定策与全自动生成**：
   用户一旦确认，Agent **不再向用户繁琐提问**，立即由系统智能拍定：
   - 所有数据表的字段列表、主外键、类型（varchar/int/datetime/bool/money）；
   - UI 组件选型（input/select/date/switch/upload）；
   - 搜索筛选维度（like/eq/range）；
   - 动作矩阵与台账只读限制（如流水表禁止修改删除）；
   - 基础业务字典自动装配；
   - **执行能力库装配**：调用 `genplus_install_capability` 将已选的能力包（如 `landing_poster`, `dict`, `dashboard` 等）精准落库并写入配置！
   按序调用 MCP 工具（`create_tenant` -> `dict` -> `module` -> `fields` -> `design` -> `install_capability` -> `generate` -> `start` -> `screenshot`）一气呵成完成上线，交付访问链接与真机截图！

## 路线 B：细节模式 (Detailed Mode / 深度定制)

适用于企业级复杂业务、数据敏感、强审计规范或需要逐字段严格把控的系统。

### 阶段一：项目立项与基础信息对齐 (必须交互)

当用户选择细节模式时：

1. **主动向用户发起交互式立项问卷**（使用 `ask_question` 工具）：
   * **项目全称与英文标识**：向用户确认系统的正式中文名与英文标识（如 `wms` / `edu_asset` / `catering`）；
   * **核心应用场景与角色定位**：询问系统的主要使用群体与核心业务闭环；
   * **门禁模式（Auth Mode）**：
     - `rbac`（完整权限控制，角色 + Casbin 策略，生产推荐）
     - `users`（成员账号登录，统一权限）
     - `simple`（单一轻量门禁口令）
   * **视觉皮肤与色系**：
     - 皮肤风格：`macos-modern`（macOS 现代感微拟物）、`classic`（企业稳重）、`minimal`（极简清新）
     - 主题色调：`blue`（科技蓝）、`emerald`（生机绿）、`violet`（优雅紫）、`amber`（暖阳橙）

等待用户反馈提交后再进入下一阶段。

### 阶段二：业务实体与模块划分研讨 (需求方案草案)

收到用户录入的基础信息后，Agent 需拟定业务实体草案，并**再次与用户研讨确认**：

1. **分组与模块划分**：
   * 将系统划分为 1~3 个业务分组（如：基础数据、业务流转、统计报表）；
   * 在每个分组下设计具体数据模型（表名、主键、业务字段）；
2. **枚举字典规划**：
   * 提炼需要配置的标准字典（如状态字典、类型字典、审核结果字典）；
3. **输出方案卡片并征求用户反馈**：
   * 罗列模块清单、核心字段与对应关系；
   * 询问用户：“这个模块划分和字段规划是否满足您的需求？是否有需要增加或删减的实体？”

---

## 阶段三：两级能力天花板与动作矩阵确认 (安全与审计设计)

根据 GenPlus 两级能力天花板架构，必须与用户确认每个模块的**物理能力上限**：

1. **明确只读 / 审计模块**：
   * 诸如“操作日志”、“库存流水台账”、“财务对账单”等审计类模块，建议物理关闭 `create`、`edit`、`delete`，仅保留 `export` 和 `detail`；
   * 询问用户是否同意该模块的只读限制；
2. **确认常规业务模块的动作全集**：
   * 是否支持 `export`（导出）？
   * 是否需要 `batch`（批量操作）？
3. **确认能力库装配矩阵 (前台触达与后台增强，拒绝纯单薄CRUD)**：
   * **前台触达能力 (B+C 双端业务闭环)**：
     - `landing_poster`：是否需要 C 端推广落地页、扫码 PV 统计与后台“推广码”弹窗？
     - `landing_form`：是否需要面向用户的公开动态收集表单（线索收集、预约登记、活动报名）？
     - `landing_portal`：是否需要前台检索、卡片列表与在线提报复合门户（招聘门户、展厅、活动中心）？
     - `landing_cms`：是否需要企业官网大屏、核心特性网格与资讯文章系统？
   * **后台系统增强能力**：
     - `dashboard`：是否需要首页经营分析大屏与核心指标聚合卡片？
     - `dict`：是否需要数据字典集中维护与状态联动？
     - `file`：是否需要文件、图片与附件存储？
     - `flow`：是否需要多级工单审批流？
     - `io` (导入导出) / `batch` (批量操作) / `tree` (树形层级) / `recycle` (软删回收站) / `job` (定时任务) / `message` (站内信) / `security` (水印加固) / `print` (单据打印)。

---

## 阶段四：方案终审门禁 (Gate Review & Sign-Off)

在调用任何生成工具前，Agent 必须向用户呈现一份结构化的《项目构建终审蓝图》：
* **基本信息**：系统名称、端口、数据库名、门禁模式、皮肤色系
* **字典清单**：包含的所有枚举项与色彩
* **分组与模块**：各模块名称、表名、字段清单、动作矩阵上限
* **系统扩展能力**：已选装的能力包
* **前台触达微页面**：若装配了 landing 能力，说明前台访问路径与功能

明确提示：“【构建门禁】以上为即将构建的完整蓝图，请确认是否立即执行建档生成？”
**只有在用户明确确认（例如点击同意或回复“确认执行”）后，才能进入阶段五！**

---

## 阶段五：执行自动化构建与真机校验 (调用 GenPlus MCP)

获得用户正式签署后，按顺序调用工作台 MCP 工具：
1. `genplus_create_tenant`：创建项目档案；
2. `genplus_save_dict`：逐组录入业务枚举字典；
3. `genplus_create_model_group`：建立模块分类分组；
4. `genplus_create_module` & `genplus_add_fields`：创建业务模型与字段；
5. `genplus_configure_design`：写入皮肤配置与动作能力矩阵；
6. `genplus_install_capability`：逐项安装并配置确认的能力包（支持传入配置对象）；
7. `genplus_generate_project`：触发生成站编译并导出完整源码；
8. `genplus_manage_service`：启动子后台独立实例（`action: 'start'`）；
9. **真机全链路冒烟门禁 (Mandatory Verify Gate)**：调用 `/api/verify/:tenantId`（`boot: true`）执行全面冒烟检测，严格要求所有用例（工程结构、TypeScript 语法、物理建表、Cookie 租户隔离、组件具名槽、真实登录与能力探针）`fail=0` 且 `skip=0` 全部通过，否则严禁宣告上线；
10. **数据库与数据检验**：调用 `genplus_db_query` 检查物理表结构与初始种子数据；
11. **真机画面截图与交付**：调用 `genplus_take_screenshot` 截取子后台（及前台 H5/官网微页面）真实运行画面（自动断言未重定向至登录页且数据渲染完整），为用户交付完整系统证据链；
12. 向用户汇报访问链接、账号凭证、数据库连接串与预览截图。

---

## 阶段六：B端中台 + C端微页面一体化 (Front+Back Dual-End Cohesion / 可选扩展)

当业务场景涉及对外公开页面（如公众号渠道二维码展示与扫码推广、问卷登记、活动报名、公开商品展示页等）时：
1. **自动规划 C端路由与免鉴权接口**：
   - 页面路由：如 `/p/[scene]` 或 `/p/[id]`，采用免登录的独立移动端卡片布局（`definePageMeta({ layout: 'blank' })`）；
   - 服务端接口：在 `server/api/public/*` 开放轻量免鉴权 API（如二维码 Base64 生成、模拟扫码回调、公开登记提交）；
2. **打通数据闭环**：
   - C端用户行为（扫码/提交）即时写入 B端后台数据台账（如 `mp_scan_log`），并原子自增业务主表计数器；
   - B端后台数据表格（如 `/admin/channelQrcode`）在操作列提供一键直达“推广页”快捷按钮；
3. **调用 MCP 落地与验证**：
   - 调用 `genplus_create_public_landing` 一键建立 C端微页面模板与公开 API；
   - 调用 `genplus_take_screenshot` 对 `/p/:scene` 拍摄真机移动端预览截图，交付完整商业闭环！
